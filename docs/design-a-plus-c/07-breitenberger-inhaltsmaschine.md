## Entwicklerbrief (Wortlaut)

```
AUFTRAG: Inhaltsarchitektur wie Praxis Breitenberger (München),
Optik NICHT übernehmen.

1. NICHT BAUEN
- Kein visuelles Klonen (Farben, Raster, Fotostil, Komponenten 1:1).
- Kein „Lanserhof/Breitenberger-Look“.
- Keine Praxis-Reportage-Fotografie als Pflicht, solange keine
  professionellen Fotos vorliegen.
- Keine Heilversprechen, keine Indikations-Claims wie bei ihm,
  wenn HWG sie nicht trägt. Wir sind STRENGER — das ist Vorsprung
  für Google und Anzeigen.
- Geräte-URLs nicht als Money-Pages behandeln (NLS, EAV, Vieva).
  Sie stützen Anliegen, sie ersetzen sie nicht.

2. DOCH BAUEN — Inhaltsmaschine

2.1 Anliegen-Hubs (Hashimoto-Logik → unsere drei)
    Bei ihm: eine Erkrankung/ein Anliegen = eine Money-Page
    (Leistung + Ort im Title, Symptom-Intent, Cluster drumherum).
    Bei uns dieselben drei Hubs, bereits vorhanden:
      /schmerztherapie-augsburg
      /psychotherapie-augsburg     (Erschöpfung / Psyche)
      /naet-methode-allergie-behandlung
    Jede dieser Seiten muss suchintent-fähig sein:
      Symptome, Einordnung, was die Praxis tut, was sie NICHT tut,
      nächster Schritt, NAP, FAQ, Quellen.
    Tiefe Ratgeber-URLs nur, WENN sie den Hub stützen.
    Kein Ratgeber-Friedhof. Nicht-stützende Archivseiten bleiben
    noindex (gewollt).

2.2 Title-Formel
    Leistung + Ort, nicht Gerät + Ort.
    Gut:  „Heilpraktiker für Schmerz in Augsburg | Peter Rauch“
    Schlecht: „NLS-Diagnostik Metatron Augsburg“ als Haupt-Money-Title.
    H1: Leistung in Augsburg. Lead: Hochzoll, Friedberg, Lechhausen.

2.3 Personenseite
    /ueber-mich: benannte Ausbildungen, Daten, Erlaubnis
    (26.12.2006), PT, BDHN, Amt — nicht nur Fließtext „ich arbeite seit…“.
    Byline auf Hubs. Fach-Reviewer/Quellen nachziehen
    (bei ihm: Redaktion Dr. Schaenzler, GU-Buch — wir brauchen
    eigene, wahrheitsgemäße Belege, keine fremden Titel).

2.4 Kosten / FAQ / Redaktion
    Eigene Seiten bzw. feste Blöcke: Erstgespräch & Kosten, FAQ,
    Quellen/Redaktion. Jede Money-Page: FAQ + Disclaimer + NAP.
    Schema (MedicalBusiness, FAQPage) beibehalten und auf Hubs
    ausweiten.

2.5 NAP auf fast jeder relevanten Seite
    Adresse, Telefon, Stadtteil im Fließtext (Hochzoll), nicht nur Footer.
    Friedberg und Lechhausen dort, wo der Intent lokal ist.
    Video-Termin optional — erst nach Freigabe, kein Muss.

2.6 Intent und KI/GEO
    Seiten so schreiben, dass klare Sätze zitierbar sind
    (ChatGPT/AI-Overviews): Definition, Grenze (kein Arzt), Ort, nächster Schritt.
    Geräte-Inhalte an Anliegen koppeln, nicht isoliert ranken lassen.

3. OPTIK (getrennt von der Inhaltsmaschine)
    A+C laut docs/design-a-plus-c/00-FESTLEGUNG.md
    Parsley-Stimmung auf Gesprächsseiten, Neko-Hinweis nur Diagnostik.
    Sage Akzent, nicht Fläche. Clay = ein CTA.

4. INDEX
    18 Hubs + Start: index.
    Tiefe Archiv-URLs: noindex bis der Hub sie braucht.
    Alte WordPress-Pfade der 18 Hubs unverändert.

5. AKZEPTANZ
    Eine Anliegen-Seite gilt als „Breitenberger-logisch“, wenn:
    - Title = Anliegen + Augsburg
    - Above-the-fold: wer, für wen, wo, was nicht
    - Körper: Symptome / Einordnung / Verfahren (ohne Heilversprechen)
    - Byline + Quelle oder „Redaktion Praxis“
    - FAQ (3–6), NAP, ein Clay-CTA
    - Interner Link zum stützenden Ratgeber NUR wenn vorhanden
```
